# v0.7.0 — 可信模型能力发布

v0.7.0 是一个 minor 版本：LiteLLM 里发现的模型，只有在能力信息足够可信时才会作为正常模型发布到 Pi。incomplete / invalid 的模型不再伪装成正常模型，元数据源故障有了可恢复、可解释的路径，而"我了解缺失、仍想用"变成一个用户显式执行的动作。

## Highlights

- 正常模型发布前先过可信度门槛：能力不足的模型不再冒充正常模型。
- 元数据源故障可由 LKG（last-known-good）历史完整快照接管，且有明确的拒绝规则。
- 新命令 `/litellm-accept-degraded <endpoint-id> <model-id>`：显式接受降级，用户必须主动确认。
- 支持 reasoning 但没有 selectable levels 的模型，仍然正确标记为 reasoning。
- `/litellm-diagnostics` 说明每个模型的配置状态、数据来源与失败原因。

## 可信的模型发布（Trustworthy model publication）

只有能力信息完整可信（上下文窗口、输出上限、工具调用、reasoning 等足以让宿主正确使用）的模型，才会作为正常模型注册到 Pi：

- unknown capability 不再被当成 `false` 或 `true` 展示——未知就是未知；
- 不再发布 `contextWindow=0` 或 `maxTokens=0` 的模型；
- incomplete metadata 的模型不会伪装成正常模型，而是明确落到"未完成"状态。

换句话说：`/model` 里看到的正常模型，意味着它的能力信息真的可信，而不是"拼出了一个看似完整的配置"。

## 元数据故障与 LKG（Metadata failure and LKG）

- 元数据获取失败（超时、5xx、网络不可达等）时，如果有仍可信的历史完整快照（LKG），模型继续可用并标注为 LKG；
- LKG 没有固定 TTL：年龄本身不会使快照失效，标注会写明来源与数据年龄；
- 出现新的 live fact 且与旧快照冲突时，旧 LKG 会被拒绝，不会用过期数据覆盖新鲜数据；
- 没有任何可信数据时，模型不会"偷偷"以正常状态发布，而是落到未完成状态等待显式处理。

## 显式降级模式（Explicit degraded mode）

```text
/litellm-accept-degraded <endpoint-id> <model-id>
```

- 用户必须**主动执行**才会接受，扩展不会自动降级发布；
- 接受后模型仍标记为降级：degraded 不等于 fully configured，`/litellm-diagnostics` 会继续列出剩余缺口；
- 重启 Pi 后需要重新接受；
- 身份不明（invalid / ambiguous identity）、元数据非法或无法匹配的模型不能通过普通 accept，命令会拒绝且不会显示接受成功。

## Reasoning 模型

- 支持 reasoning、但没有 selectable thinking levels 的模型，仍会被正确标记为 reasoning；
- 没有 level 不代表不支持 reasoning，`/thinking` 只在确实存在可选档位时提供切换。

## Diagnostics

`/litellm-diagnostics` 的"模型配置"段现在让用户能看懂每个模型的状态与原因：

- **configured**：能力完整可信的正常模型；
- **incomplete**：缺了哪些能力字段；
- **invalid**：身份/元数据不可信，不可通过普通 accept；
- **LKG**：正在使用历史完整快照，含来源与数据年龄；
- **degraded**：已被显式接受的降级模型及剩余缺口；
- 每种非正常状态都会说明 provenance 与失败原因，便于判断是网络问题、上游缺字段还是身份匹配失败。

diagnostics 依旧只读已有状态，不发起模型请求、不显示 API Key 或 LiteLLM 地址。

## Real Pi 0.87.1 E2E

发布前，release candidate 必须通过完整的交付 CI 与 **Real Pi 0.87.1 E2E**：用 Pi 自己的 `pi install` 安装不可变 Git commit，在隔离 HOME/XDG/`PI_CODING_AGENT_DIR` 与本地 fake LiteLLM 中验证真实命令注册、provider/model 可见性、operational limits、凭据隔离、endpoint activation、diagnostics 与 Runtime Identity。本版本的可信发布、LKG 与 degraded 接受行为均在该真实宿主门禁中覆盖。

## 安装 / 升级

跟随最新稳定 main：

```bash
pi install git:github.com/rpchen/pi-litellm-provider
```

或锁定 v0.7.0：

```bash
pi install git:github.com/rpchen/pi-litellm-provider#v0.7.0
```

从 v0.6.0 升级后重启 Pi 即可；现有 endpoint 配置、凭据与启用状态不受影响。升级后首次发现会重新评估每个模型的配置状态，之前"看起来正常"的不完整模型可能改列为未完成或需要显式接受降级——这是预期行为。
