# v0.6.0 — Runtime Identity 与审计导出

v0.6.0 是一个 minor 版本：正在运行的扩展 artifact 现在拥有自己的不可变身份 Runtime Identity，排查问题时不再需要猜测 Git commit 或分支。同时 `/litellm-audit-export` 正式可用，可一键导出已注册模型清单与完整 Runtime Identity。

## Runtime Identity

正在运行的 artifact 通过三个字段标识自己：

- `Plugin Version`：扩展版本（`0.6.0`），
- `Artifact Digest`：artifact 的确定性 SHA-256 摘要，
- `Core Commit`：内嵌的 `litellm-discovery-core` commit（`8e155e0efe90f1e9e7c8e973239c206a97011477`）。

三处同源，可在以下位置查看：

- `/litellm-diagnostics` 末尾的 `Runtime Identity` 块（短形式），
- `/litellm-audit-export` 导出 JSON 中的 `runtimeIdentity`（完整值），
- 扩展启动日志中的 `LiteLLM Runtime Identity plugin=… artifact=… core=…` 行。

```text
Runtime Identity

Plugin Version   0.6.0
Artifact         f149674c
Core Commit      8e155e0e
```

反馈问题时，请附上 `/litellm-diagnostics` 中的 Runtime Identity 段落，或 audit 导出文件中的 `runtimeIdentity` 对象。

## 新增：`/litellm-audit-export`

`/litellm-audit-export [endpoint-id]` 把当前已注册的 provider 模型清单导出到 `<agentDir>/litellm-audit/` 下的新 JSON 文件，并在界面中报告绝对路径。无参数时导出全部已激活 endpoint；传 endpoint id 只导出该 endpoint。

报告只包含 allowlist 字段：

- 不包含 API Key，
- 不导出 LiteLLM baseUrl，
- 不包含原始上游响应与可扩展设置，

同时保留模型 id、协议、推理档位、能力、价格与上下文/输出上限等真实注册值，适合作为提交问题时的模型配置证据。导出失败不会影响 provider 注册与轮询。

## Real Pi 0.87.1 E2E 覆盖

常设真实宿主门禁通过 Pi 自己的 `pi install` 安装不可变的 candidate commit，在隔离 HOME/XDG/`PI_CODING_AGENT_DIR` 与本地 fake LiteLLM 中验证：扩展加载成功、diagnostics 短值与 candidate 一致、audit 含完整值且模型无 baseUrl 泄露、startup 含同一 identity、全程不依赖 `.git`。

## 安装 / 升级

跟随最新稳定 main：

```bash
pi install git:github.com/rpchen/pi-litellm-provider
```

或锁定 v0.6.0：

```bash
pi install git:github.com/rpchen/pi-litellm-provider#v0.6.0
```

从 v0.5.0 升级后重启 Pi 即可；现有 endpoint 配置、凭据与启用状态不受影响。

## 验证

发布前，release candidate 必须通过完整的交付 CI 与 **Real Pi 0.87.1 E2E**。

内嵌的 discovery Core 仍固定为 `8e155e0efe90f1e9e7c8e973239c206a97011477`。
